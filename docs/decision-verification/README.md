# 报告决策与版本证据验收

本轮聚焦报告质量与版本对比，未部署；账号、所有权、匿名成功额度及既有用户数据保留。

## 实现

- 报告新增可选 `validationGuide`，保存三个按优先级排列的风险。每项包含排序理由、事实/推断/假设类型、依据、影响、验证对象、步骤、需收集证据、参考判据及理由；保存继续、调整、暂缓条件和信息不足标记。
- 真实模型提示词要求每个核心批评有依据和行动，不虚构访谈、市场、竞品或付费数据。存在指南时校验三个风险和必需字段；旧报告缺少指南仍可读取，以明确标记的建议模板降级。
- Mock 提供可在一周内实施的演示实验，不声称真实访谈或实测结果。数字仅作为探索参考，说明小样本限制。
- 报告、工作台和版本页优先展示指南结论及参考判据；评分注明是辅助描述判断。Markdown 保存新指南；新迭代草稿带入指南步骤及参考判据，不宣称验证已完成。
- 版本接口复用现有原始输入与报告 JSON，新增响应字段，不新增数据库表。对比实际父报告，提供输入原文语句增删、仍被提出/未再提出/新增风险提示及下一步证据。
- 风险标题按字面比对，不做语义理解；报告未再提到某项风险不代表缓解。系统未核验外部试验记录，不显示实证降低的断言。
- 版本读取错误可重试，加载前清理旧组；版本选择默认与展示的最新版本一致。
- 报告目录 hash 跳转不再重挂载页面，固定顶栏留出滚动位置。标题减少动态效果偏好在播放前及播放中切换时生效，减少动态模式禁用平滑滚动。

## 本轮 Playwright MCP 实际流程

使用新建独立 `example.test` 验收账号，邮箱开发捕获，AI 为 Mock。原测试账号登录失败后未修改其密码，换新账号完成流程。

1. 新建校园二手交易项目，生成 V1（报告 251）。
2. 从 V1 进入草稿，改为一个校区、减少功能，并明确尚未执行验证；刷新后全文恢复。
3. 提交生成 V2（报告 252），所属项目 251，父报告为 V1。
4. 完整报告显示三个风险、步骤、证据、参考判据及条件，信息不足明确标记。
5. 版本对比正确与 V1 对照：4 条新增/改写、3 条删除/替换；V2 默认选中。刷新后仍能重新读取、选择及返回来源报告。
6. 打开故意无效的版本地址，显示错误与重试按钮，重试仍给一致错误，没有残留先前项目；随后恢复有效项目。
7. 标题逐字期间输入正常，读取到中间标题“把产”及完整输入；后续输入、侧边栏更新不重播。
8. 工作台按钮1440px和800px同一行、40px高；390px纵向排列，均无横向溢出。
9. 版本页保留一个顶部来源返回按钮。报告目录定位后指南距顶端约84px，避免被顶栏遮挡。

## 未验收与局限

真实模型未调用；提示词的引用准确性、风险与具体产品的匹配、参考判据合理性仍需真实模型与人工验收。Mock 的实验为演示模板，不能当作市场验证。旧报告 UI 的降级分支通过代码和自动检查，本轮未另造旧数据库报告做浏览器实测。浏览器已验收读取失败重试；真实 AI 超时/供应商故障后的浏览器提交重试未注入测试，正常失败不扣成功额度仍由服务端集成测试覆盖。系统减少动态设置的实际开关未在当前浏览器工具中模拟，分支已实现。既有报告 Markdown 不自动回写；下载文件落盘未重测。

## 3人用户测试提纲

招募3位目标用户，分别进行15分钟测试，同样任务，不先解释导航。

1. 输入自己的想法、生成报告，边做边说；记录停顿、误点、返回失败和求助点。
2. 问“哪条建议有用，为什么？哪条不明白？”让用户指出具体风险与依据。
3. 合上报告，让用户复述：这周找谁、做什么、记录什么、什么结果会继续/调整/暂缓。
4. 修改想法生成下一版并对比，问“哪些只是描述改了，哪些已经有证据？”观察是否把分数变化当实测。

每人保留原话与卡住步骤；汇总3人是否能独立说出对象、动作、证据、决策条件，按最常见阻碍排序修复。
